# 規格:頁尾的資料版本下載時間與資料來源連結

Status: ready-for-agent

## 問題陳述

頁尾目前只寫國服與台服的資料版本號(例如國服 78.2.0、台服 51.4.0),外加一行純文字「遊戲資料來自 Kengxxiao/ArknightsGameData 與 arkntools/arknights-data-tw-for-maa」。玩家看不出這份資料是什麼時候抓的,版號本身也不直觀,國服與台服的版號還不能互相比較。資料來源只是純文字,無法點過去查看;頭像的資料來源完全沒寫。

## 解決方案

頁尾改成一行:「[國服] 78.2.0 · 2026-10-19 12:14(UTC+8) · [台服] 51.4.0 · 2026-10-19 12:14(UTC+8) · [頭像]」。

- 每個伺服器的資料版本後面接該服資料的下載時間,一律以台灣時間顯示到分。
- 「國服」「台服」「頭像」三個字是超連結,在新分頁開啟各自資料來源的 GitHub 資料庫。
- 懸停在這三個字上時,顯示資料來源名稱,例如「資料來源:Kengxxiao/ArknightsGameData」;手機上點了直接跳過去。
- 原本那行純文字的資料來源說明拿掉。

## 使用者故事

1. 身為玩家,我想在頁尾看到國服資料的下載時間,這樣知道國服資料有多新。
2. 身為玩家,我想在頁尾看到台服資料的下載時間,這樣知道台服資料有多新。
3. 身為玩家,我想讓國服與台服的下載時間分開顯示,這樣只有一服更新時也看得出來。
4. 身為玩家,我想讓下載時間一律以台灣時間顯示到分,並標「UTC+8」,這樣不論在哪裡開網頁,看到的時間都一樣,截圖比對也不會混淆。
5. 身為玩家,我想讓下載時間緊接在該服的資料版本後面,這樣一眼對得上哪個時間屬於哪一服。
6. 身為玩家,我想點頁尾的「國服」就在新分頁開啟國服資料來源的資料庫,這樣能自己查看原始資料。
7. 身為玩家,我想點頁尾的「台服」就在新分頁開啟台服資料來源的資料庫,這樣能自己查看原始資料。
8. 身為玩家,我想點頁尾的「頭像」就在新分頁開啟頭像資料來源的資料庫,這樣知道頭像從哪來。
9. 身為玩家,我想讓連結在新分頁開啟,這樣回來時已選的關鍵字與篩選條件還在。
10. 身為桌機玩家,我想在懸停「國服」「台服」「頭像」時看到資料來源名稱,這樣點之前就知道會連到哪裡。
11. 身為手機玩家,我想點這三個字就直接開啟連結,不必點兩下。
12. 身為手機玩家,我想讓頁尾在窄螢幕上自動換行,這樣網頁不會出現水平捲動。
13. 身為玩家,我想讓頭像只顯示連結、不顯示版本與時間,這樣頁尾不會出現沒有意義的數字。
14. 身為維護者,我想讓線上建置自動記下每個伺服器資料的下載時間,這樣不用手動填。
15. 身為維護者,我想讓離線建置沿用快取當初的下載時間,而不是這次建置的時間,這樣離線重建不會讓資料看起來比實際新。
16. 身為維護者,我想讓舊的快取(還沒有下載時間記錄)也能建置,並以該服資料檔的修改時間當下載時間,這樣不用為了這個功能重新下載。
17. 身為維護者,我想讓資料來源的位置只在一個地方定義,建置用來下載、頁尾用來顯示,這樣換來源時不會兩邊不一致。

## 實作決策

- **資料版本加上下載時間。** 索引原本為每個伺服器記錄版號;改為每個伺服器各記一筆資料版本:版號,加上該服資料的下載時間。時間存成帶時區的標準時間字串,格式化留給顯示端。
- **下載時間的取得。**
  - 線上建置下載某個伺服器的資料時,在該服的快取裡寫一個時間記錄,值為該服所有檔案下載完成的時間。
  - 離線建置讀這個記錄。
  - 舊快取沒有記錄時,改用該服幹員表檔案的修改時間。
- **建置的輸入。** 建置函式維持純函式:下載時間由建置腳本讀好,和原始資料一起作為該伺服器的輸入傳入,建置函式只負責放進索引。
- **資料來源清單。** 國服、台服、頭像三個資料來源的名稱(例如 Kengxxiao/ArknightsGameData)與 GitHub 資料庫網址集中定義一次。建置腳本的下載位置與頁尾連結都從這份清單衍生。資料來源不寫進索引:它是固定的程式設定,不是隨資料變動的內容。
- **查詢端的公開函式。** 新增一個純函式:輸入索引,輸出頁尾要顯示的項目清單。
  - 每個伺服器一項:顯示名(國服/台服)、版號、已格式化的台灣時間字串(「YYYY-MM-DD HH:mm(UTC+8)」)、資料來源名稱與網址。
  - 頭像一項:只有名稱與網址。
  - 時間格式化固定用台灣時區,不受瀏覽器或執行環境的時區影響。
  - 索引沒有台服資料時,不列台服那一項。
- **頁尾。**
  - 依上述清單排成一行,各項以「·」分隔,窄螢幕可換行。
  - 「國服」「台服」「頭像」是在新分頁開啟的超連結,並阻擋開啟頁取得原頁面的控制權。
  - 懸停提示用瀏覽器原生的提示,內容為「資料來源:<名稱>」。
  - 移除原本的純文字資料來源說明。

## 測試決策

- 好的測試只驗證外部行為:給定輸入,驗證使用者看到的內容,不驗證索引欄位排列或內部結構。
- **建置 → 查詢(Vitest)。**
  - 把各伺服器的下載時間連同手寫的小型原始資料餵入建置,再以查詢端的新公開函式取出頁尾項目。
  - 斷言國服與台服的版號、台灣時間字串(例如輸入 2026-10-19T04:14:00Z 得到「2026-10-19 12:14(UTC+8)」)、資料來源名稱與網址,以及頭像項目沒有版號與時間。
  - 另一個案例:沒有台服資料時不列台服。
  - 先例:現有建置 → 查詢測試的手寫資料片段與 server 輔助函式。
- **Playwright 煙霧測試。**
  - 在既有桌機煙霧測試裡,驗證頁尾含兩個「版號 · 日期 時分(UTC+8)」的格式。
  - 驗證「國服」「台服」「頭像」三個連結指向各自的資料來源網址,並設定在新分頁開啟。
  - 手機寬度測試已涵蓋整頁沒有水平捲動,頁尾一併受檢。
- 下載時間的取得(寫時間記錄、讀時間記錄、退回檔案修改時間)屬於建置腳本的檔案操作,不另寫單元測試;以實際執行線上與離線建置各一次確認。

## 不在範圍內

- 頭像的下載時間與版本。
- 資料來源的 commit 或資料夾層級連結(只連到資料庫首頁)。
- 依瀏覽器時區顯示時間、相對時間(例如「3 天前」)。
- 頁尾以外位置的資料來源說明(README 已有,不變)。
- 自訂樣式的懸停提示框。

## 其他備註

- 名詞依 CONTEXT.md:資料版本(版號加下載時間)、資料來源(遊戲資料或頭像所在的公開資料庫)、伺服器。
- 國服與台服的版號各自編號、不能比較大小,頁尾並列時不做任何比較。
