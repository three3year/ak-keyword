# 規格:外觀開關

Status: ready-for-agent

## 需要你決定的

### 測試切點放哪?

決定(2026-10-20):只用 e2e 真實資料。

- e2e 真實資料(建議):沿用手機與煙霧測試的 Playwright,在模擬亮色與暗色系統下切換外觀,檢查頁面底色、記住選擇、手機標題列兩行與懸浮鈕。只有一個切點,而且是最高的一層;底色斷言只比對「亮與暗不同」與「跟隨系統等於系統那一色」,不寫死色碼。
- e2e 加上記住選擇的單元測試:多一個切點。但目前記住伺服器的做法沒有單元測試,單元測試也沒有瀏覽器環境,要另外補環境。

### 重新整理時會不會先閃一下錯的顏色?

決定(2026-10-20):在網頁最前面先套用。

選了固定亮色或暗色、而系統是另一色時,如果等網頁程式載入後才套用外觀,重新整理會先閃一下系統色。

- 在網頁最前面先套用(建議):頁首放一小段程式,讀記住的外觀並在畫面出現前套用,不會閃。代價是讀取記住值的規則在兩處各寫一次。
- 等網頁程式載入後再套用:只寫一處,但每次重新整理都可能閃一下。

### 懸浮鈕會不會擋住最後一張結果卡?

決定(2026-10-20):手機寬度下內容底部多留懸浮鈕的高度。

- 手機寬度下內容底部多留懸浮鈕的高度(建議):捲到底時最後一張卡完整露出。
- 不處理:最後一張卡的右下角會被懸浮鈕蓋住,要捲回去才看得到。

### 開關有幾種狀態?

決定(2026-10-20):三態,跟隨系統、亮色、暗色,預設跟隨系統。

- 三態:預設行為與現在完全一樣,使用者可改成固定亮或固定暗。
- 兩態亮與暗:第一次依系統決定起始值,之後不再跟系統連動。
- 兩態,預設固定亮:目前跟著系統變暗的使用者會看到網站變回亮的。

### 開關放在哪裡?

決定(2026-10-20):標題列,伺服器切換旁邊。

- 標題列,伺服器切換旁邊:和伺服器切換一樣是全站設定,放在一起好找。
- 標題列最右端:手機上與「關鍵字」鈕爭右側空間。
- 關鍵字面板裡:手機上要打開抽屜才找得到。

### 要不要記住選擇?

決定(2026-10-20):記住,做法同伺服器切換。

- 記住:存在瀏覽器裡,下次開站沿用;存不了就回預設。
- 不記住:重新整理就回預設。

### 開關長什麼樣?

決定(2026-10-20):文字分段鈕,樣式同伺服器切換;手機上「關鍵字」鈕另外換位置,不和開關擠在一起。

- 文字分段鈕:和伺服器切換一致,最寬。
- 圖示分段鈕:較窄,但要自己畫圖示。
- 單一圖示鈕輪流切換:最省空間,但看不出下一次會變成什麼。

### 這個概念叫什麼?

決定(2026-10-20):外觀;三個狀態叫跟隨系統、亮色、暗色,已寫入詞彙表。

- 外觀:Windows 與 macOS 繁中介面的用語。
- 配色:專案裡已用來講各種色系,容易混淆。
- 主題:暗示未來會有更多樣式。

### 鈕面文字用全名還是縮寫?

決定(2026-10-20):鈕面寫「系統 / 亮 / 暗」,懸停文字與讀屏器用全名。

- 縮寫:寬度與伺服器切換相近。
- 全名:比伺服器切換寬一倍多,手機上很擠。
- 「自動 / 亮 / 暗」:與正式名稱不一致。

### 資料載入中或載入失敗時,開關要不要出現?

決定(2026-10-20):一直顯示。

- 一直顯示:外觀不需要資料;錯誤頁也能切;標題列不會因為開關晚出現而跳動。
- 同伺服器切換,載入完才出現:兩個開關同進同出,但錯誤頁無法切外觀。

### 跟隨系統時要不要標示目前是亮還是暗?

決定(2026-10-20):不用,頁面本身就看得出來。

- 不用:只高亮「系統」那一格。
- 在「系統」格補註目前結果:多一點資訊,但要監聽系統變化更新文字。

### 手機上「關鍵字」鈕放哪?

決定(2026-10-20):改成右下角的懸浮鈕,標題列不再有它。

- 標題一行、三個控制項第二行:固定兩行,關鍵字鈕靠右。
- 右下角懸浮鈕:標題列較矮,但懸浮鈕會蓋到內容。
- 標題與關鍵字鈕同一行、兩個分段鈕第二行:標題長時會擠。

### 懸浮鈕長什麼樣?

決定(2026-10-20):膠囊鈕,強調色底、白字,文字照現在的「關鍵字(2)」。

- 膠囊鈕:不用圖示,一看就知道是什麼。
- 圓鈕加數量徽章:占位最小,但要畫圖示,也較難猜。

### 抽屜打開時懸浮鈕怎麼處理?

決定(2026-10-20):隱藏,抽屜關了再出現。

- 隱藏:畫面上只有一種關抽屜的方式,不和遮罩重疊。
- 留著,按了等於關抽屜:要多一個層級與狀態樣式。

### 手機標題列怎麼排?

決定(2026-10-20):固定兩行,標題一行,伺服器切換與外觀一行。

- 固定兩行:不論手機寬度都一樣,不亂折。
- 排得下就一行、排不下才折:有時只有外觀被折到第二行。

## 問題陳述

網站已有完整的暗色配色,但只會跟著作業系統或瀏覽器的設定走。想在白天用暗色、或系統是暗色卻想看亮色的使用者沒有辦法改,只能去改整台電腦的設定。

## 解決方案

標題列在伺服器切換旁邊多一個外觀開關,三格「系統 / 亮 / 暗」。預設「系統」,行為和現在一樣:跟著系統設定,系統切換時頁面即時跟著換。選「亮」或「暗」後,不論系統設定都固定用該色,選擇會被記住,下次開站沿用。開關一直顯示,資料載入中與錯誤頁也能切。

手機寬度下,標題列改成固定兩行:標題一行,伺服器切換與外觀一行。原本在標題列的「關鍵字」鈕改成右下角的膠囊懸浮鈕,抽屜打開時隱藏。

## 實作決策

- **外觀的狀態**:三個值,跟隨系統、亮色、暗色;預設跟隨系統。
- **記住選擇**:和伺服器切換用同一個瀏覽器儲存模組,新增一組讀取與存入;讀到不認得的值或存取失敗時回到跟隨系統,存不了就算了。
- **套用方式**:外觀固定時,在網頁的根元素上標記目前外觀;跟隨系統時不標記。配色令牌的暗色那組改成在兩種情況下生效:根元素標記為暗色;或根元素沒有標記為亮色、而系統偏好暗色。所以跟隨系統時完全交給瀏覽器的系統偏好判斷,程式不必讀系統設定,也自然即時跟著系統切換。瀏覽器自畫元件的配色宣告跟著同一套規則走。
- **配色令牌不變**:亮色與暗色兩組令牌的值沿用現在的,只改它們生效的條件。
- **開關元件**:文字分段鈕,沿用伺服器切換的樣式與單選群組語意;群組名稱「外觀」,三格鈕面「系統」「亮」「暗」,懸停文字與無障礙名稱用全名「跟隨系統」「亮色」「暗色」。
- **開關位置**:桌面放在伺服器切換右邊;一直顯示,不等資料載入。資料載入前伺服器切換尚未出現時,外觀開關單獨出現在原位置。
- **手機標題列**:固定兩行,第一行標題,第二行伺服器切換與外觀並排。
- **懸浮鈕**:手機寬度下的「關鍵字」鈕從標題列移出,改成固定在畫面右下角的膠囊鈕,強調色底、白字,文字與數量規則照舊;抽屜打開時隱藏;桌面不顯示。
- **避免閃色**:網頁最前面先讀記住的外觀,在畫面出現前套用;讀取規則與儲存模組一致(不認得的值或讀不到都當跟隨系統)。
- **懸浮鈕不擋卡**:手機寬度下內容底部多留懸浮鈕的高度。
- 不改資料建置、索引結構與核心查詢。

## 測試決策

- 好的測試只驗外部行為:在真實頁面上操作開關,檢查看得見的底色、選取狀態、版面位置與重新整理後的結果,不碰元件內部或配色令牌名稱。
- 底色斷言只比較相對關係:亮與暗的頁面底色不同;跟隨系統時的底色等於同一系統偏好下沒碰過開關時的底色。不寫死色碼。
- **桌面 e2e**(沿用煙霧測試):
  - 系統模擬亮色,沒碰過開關時「系統」被選取;切到「暗」底色改變;重新整理後仍是暗色、仍選「暗」;切回「系統」底色回到亮色。
  - 系統模擬暗色,選「亮」後頁面是亮色;把系統模擬切回亮色再切暗色,頁面維持亮色。
  - 選「系統」時,切換系統模擬的亮暗,頁面即時跟著換,不必重新整理。
  - 開關三格有全名的無障礙名稱,群組名稱為「外觀」。
- **手機 e2e**(沿用手機測試):
  - 標題列兩行:伺服器切換與外觀在同一行、在標題下方。
  - 「關鍵字」鈕在畫面右下角,選了搜尋條件後文字顯示數量;打開抽屜時看不到它,關了又出現。
  - 加了開關後仍沒有水平捲動。
- 既有手機測試用「關鍵字」名稱找抽屜鈕的寫法照樣適用,只要確認改位置後仍按得到。
- 開關在載入失敗時也出現,不寫成 e2e(沒有現成的方式讓真實資料載入失敗),靠程式碼審查確認。

## 不在範圍內

- 新的配色或亮暗以外的外觀。
- 調整現有亮色或暗色令牌的值。
- 跟隨系統時標示目前實際是亮還是暗。
- 桌面標題列除了多一個開關以外的版面變動。
- 依時間自動切換外觀。

## 其他備註

- 詞彙表已新增「外觀」。
- 現在只有一處依系統偏好切換配色;寫死在樣式裡的顏色(星號、遮罩、對話框陰影等)本來就不分亮暗,不受影響。
