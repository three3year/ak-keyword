# 03 — /update-data skill 與 README

**What to build:** 維護者在 Claude Code session 裡輸入 /update-data,agent 就照專案 skill 跑完整個資料更新,並在該停的地方停下來問維護者。skill 寫成 agent 照著做的步驟(寫法參考 writing-for-agents),內容是:

1. 用 01 的指令比對上游版本。兩服都沒有新版就回報「已是最新」和兩服版號並停下;維護者說「強制」時照樣往下跑。
2. 下載並建置索引。建置失敗時停下,回報錯誤訊息,不自行修補維護者清單。
3. 待複核配對交給 LLM 判定效果類型(依 ADR 0001,不呼叫外部 API),每一筆附幹員、敘述來源、關鍵字、規則判定、敘述原文與 LLM 判定,全部列給維護者確認;確認(或改掉幾筆)後才寫成判定檔、用現有的套用指令寫進覆寫檔,再離線重新建置,直到待複核清單是空的。
4. 從建置後的索引讀出「未分組」的術語,依官方定義提出放進哪一組、哪一行(或建議放進不當關鍵字的術語清單),寫進檔案,摘要裡標出位置與理由。
5. 用 02 的輸出列出新警告並說明影響;維護者確認是上游問題後,用 02 的指令更新已知警告清單。已消失的已知警告也一併移除。
6. 跑單元測試、打包、e2e 煙霧測試(缺瀏覽器時先安裝)。任何一項失敗就停下回報,不 commit。
7. 摘要:兩服新舊版號、新增幹員、新術語、複核筆數、新警告與已消失警告、測試結果。
8. 整次更新一個 commit:有新版時「data: 更新至陸服 X、台服 Y」;強制跑且版號沒變時寫明上游版本沒有更新,例如「data: 重新建置(上游版本未更新:陸服 X、台服 Y)」。不 push。

README 的「更新遊戲資料」改成指向這個 skill,手動步驟保留給不在 session 時使用。
